# Day 34 · W6 Redis Day 5：缓存三兄弟（穿透/击穿/雪崩）

> 2026-09-07（一）· 面试必问大题，纯概念关：是什么 → 怎么发生 → 怎么解决

## 0. 总览：三兄弟一句话区分

> 口诀：**穿透"空"、击穿"热"、雪崩"批"**
> - 穿透 = 查**不存在**的东西，永远查不到缓存
> - 击穿 = 查**一个正热**的东西，热点 key 恰好过期瞬间
> - 雪崩 = **一大批** key 同时过期（或 Redis 宕机），请求全压数据库

| 问题 | 一句话 | 核心解法 |
|---|---|---|
| 穿透 | 查不存在的 | 缓存空值 / 布隆过滤器 |
| 击穿 | 热点 key 过期瞬间 | 互斥锁 / 逻辑过期 |
| 雪崩 | 一大批同时过期 | 过期加随机 / 高可用 |

## 1. 🧊 缓存穿透（Penetration）

**是什么**：疯狂请求**数据库里根本没有的 id**（如恶意刷 id=-1 的商品、不存在的用户）
**流程**：缓存查不到 → 数据库也查不到 → **每次都打数据库**，缓存形同虚设（正常请求只有一次打库，穿透是每次请求都打库）

**解决**：
1. **缓存空值**：查不到的也缓存，设短过期（如 5 分钟）——后续同类请求直接命中空缓存，不再打库
2. **参数校验**：非法 id 直接拒绝（id<=0、格式不对直接拦）
3. **布隆过滤器**（面试加分词 ⭐）：把所有合法 id 预存进去，请求先过过滤器，**不在的一秒拦截**，根本不进缓存和数据库。缺点：有极小误判率、不支持删除

**真实场景**：黑客/爬虫遍历不存在的商品 id 刷接口，没防护时数据库被拖垮。

## 2. 🔥 缓存击穿（Breakdown）

**是什么**：一个**热点 key**（双 11 爆款、微博热搜）**恰好过期的那一瞬间**，海量请求同时发现缓存没数据 → 全部涌向数据库

**和穿透的区别（关键）**：
- 穿透：查的东西**本来就不存在**（一直查不到）
- 击穿：东西**存在**，只是缓存**刚好失效**那一瞬间被打穿

**解决**：
1. **互斥锁**：第一个请求去查库并重建缓存，其他请求先等着（拿锁的干活，没拿到的等待）——只放一个人进数据库
2. **逻辑过期**：热点 key 不设物理过期，值里带一个"逻辑过期时间"，发现过期就由后台线程异步更新，用户永远能拿到旧值兜底

**真实场景**：双 11 零点爆款秒杀，缓存一过期，10 万人同时下单查询 → 不处理数据库直接打崩。

## 3. ❄️ 缓存雪崩（Avalanche）

**是什么**：**一大批 key 在同一时间过期**（或 Redis 服务宕机），大量请求同时发现缓存没数据 → 全部压到数据库 → 数据库扛不住跟着挂

**和击穿的区别（关键）**：
- 击穿：**一个**热点 key 过期
- 雪崩：**一大批** key 同时过期 / 整个缓存服务不可用

**解决**：
1. **过期时间加随机值**：`SETEX key (300 + random) value`——把过期时间错开，避免整批同时失效（最常用）
2. **Redis 高可用**：主从复制 + 哨兵，Redis 挂了自动切换，不整体宕机
3. **服务降级/限流**：数据库扛不住时，先返回兜底数据（如默认页/提示稍后再试），保护数据库不死

**真实场景**：缓存里所有商品数据都设了"凌晨 0 点过期"→ 0 点一到全部失效 → 早高峰所有请求直打数据库 → 数据库 CPU 打满宕机。

## 4. 三兄弟对比终极表

| 维度 | 穿透 | 击穿 | 雪崩 |
|---|---|---|---|
| 本质 | 数据不存在 | 热点 key 过期瞬间 | 大批 key 同时过期 |
| 范围 | 单个/多个不存在的 key | 单个热点 key | 一大批 key / 整个服务 |
| 攻击性 | 常是恶意/异常请求 | 正常流量巧合 | 设计失误 / 宕机 |
| 第一解法 | 缓存空值 | 互斥锁 | 过期加随机 |
| 进阶解法 | 布隆过滤器 | 逻辑过期 | 高可用 + 降级限流 |
